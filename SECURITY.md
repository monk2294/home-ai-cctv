# Безопасность

## Приватное сообщение

Не создавайте публичный Issue для уязвимости. Откройте [Private Security Advisory](https://github.com/monk2294/home-ai-cctv/security/advisories/new).

Укажите:

- затронутую версию или commit;
- компонент и сценарий атаки;
- условия воспроизведения;
- возможный impact;
- минимальное исправление, если оно известно.

Не отправляйте действующие пароли, токены, cookies, приватные ключи и RTSP userinfo. Используйте отдельный тестовый стенд и искусственные секреты.

## Поддерживаемые версии

Исправления направляются в актуальный release на `main`. Старые ветки не получают гарантированную поддержку. Проект находится в стадии `0.x`; проверяйте release notes перед обновлением.

## Область угроз

Сообщайте в первую очередь о:

- обходе admin session или AI Bearer;
- доступе к go2rtc management API через Caddy;
- раскрытии секретов в API, логах, snapshots или fixtures;
- выполнении команд через media или audio parameters;
- небезопасных миграциях, backup и restore;
- уязвимостях MCP transport и инструментов.

Отсутствие HTTPS внутри закрытой LAN не считается уязвимостью само по себе. Публичная публикация без HTTPS или обход авторизации требуют отдельного анализа.

## GitHub automation

Публичный CI не использует секреты камер и self-hosted runners. Не добавляйте реальные credentials в Actions. Используйте `pull_request`, а не `pull_request_target`, для кода из fork.
