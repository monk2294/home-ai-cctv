# 55. face-check: детекция лица для присутствия

## 1. Назначение

Отвечает на вопрос «есть ли лицо человека в свежем кадре камеры». Нужен правилу света в openHAB: бортовой people-детектор камер Tapo не видит сидящего человека без корпуса в полный рост и теряет его при паузах (замеры — `docs/openhab.md` §6). Решение принято 24.11.2026 вместе с владельцем.

## 2. Контракт

Сервис `presence-check`, namespace `home-ai-cctv`, ClusterIP :8000. Доступен только из кластера (не проксируется Caddy, авторизации нет — то же доверие, что у внутренней сети backend).

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/check?camera_id=<uuid>` | 200 `{"camera_id", "face": bool, "score": float}`; 400 `{"error":"bad_camera_id"}`; 502 `{"error":"snapshot_failed"}` |
| GET | `/healthz` | 200 `{"status":"ok"}` |

`face=true`, если максимальный score лица ≥ 0,6. Ошибка снимка — 502, это не «лица нет»: потребитель обязан считать состояние неопределённым.

## 3. Реализация

- `presence/presence_check.py`: stdlib HTTP-сервер, кадр — `GET {server}/api/v1/ai/cameras/{id}/snapshot.jpg?width=1920` с AI-токеном из секрета, детекция — OpenCV `FaceDetectorYN` + YuNet.
- Модель `presence/models/face_detection_yunet_2023mar.onnx` (233 КБ, opencv_zoo, Apache-2.0, SHA-256 `8f2383e4...d2552fa4`).
- Вход 1920×1080 (`snapshot.jpg?width=1920`), inference ≈ 21 мс на homesv; кадр+детекция суммарно ≈ 1–2 с. При 1280×704 лицо сидящего человека теряется (замер — `docs/openhab.md` §6).
- Сервис stateless, single-replica. Кадр всегда свежий: snapshot идёт напрямую с камеры.

## 4. Потребитель

Правило `office_light_presence` (openHAB, эталон `deploy/openhab/office_light_presence.js`):

1. Включение света — по событию камеры `people active` (0,75 с подтверждения).
2. Сигнал камеры пропал на 10 с → правило вызывает `/check`.
3. Лицо есть → свет держим, отсчёт 10 с начинается заново.
4. Лица нет → повтор через 1 с (защита от одиночного промаха модели: отвернулся, закрыл лицо).
5. И второй промах → свет выключить.
6. Ошибка (502/таймаут) → свет не трогать, перепроверка через 10 с; страховка cron (`OFF_AFTER_MS`) осталась.

## 5. Не в объёме

- Тракинг, распознавание личностей, счёт людей.
- MJPEG-поток как источник кадров (snapshot дешевле и не занимает единственного потребителя MJPEG).
- Публикация MQTT (решение принимает правило, сервис только отвечает).
