# 20. Веб-клиент

Связанные требования: FR-01–FR-08, FR-11–FR-13, S2-FR-01–S2-FR-04. Целевые правила мобильной адаптации и двустороннего звука — в `50-stage-2.md`.

## 1. Назначение

Веб-клиент предоставляет один интерфейс администратора для добавления камер, просмотра, прослушивания звука, PTZ и событий. Этап 2 добавляет мобильную раскладку, микрофон и файловое воспроизведение. Клиент не содержит Bearer-токен ИИ и не обращается к камере напрямую.

## 2. Технические решения

- React.
- TypeScript в strict mode.
- Vite.
- React Router.
- HTTP-клиент с обработкой `Error` из OpenAPI.
- Генерация TypeScript-типов из `api-v1.openapi.yaml` через `openapi-typescript`. Сервер и клиент используют один источник контракта.
- `hls.js` для HLS без нативной поддержки.
- CSS Modules или другое изолированное решение стилей без глобальных имён.

Глобальная state-библиотека не обязательна. Состояние плеера и PTZ должно оставаться локальным до появления доказанной необходимости в общем store.

## 3. Маршруты

| Маршрут | Экран |
|---|---|
| `/login` | Вход администратора |
| `/cameras` | Список камер |
| `/cameras/new` | Мастер добавления |
| `/cameras/:cameraId` | Просмотр камеры, PTZ и события |
| `/cameras/:cameraId/settings` | Настройки и диагностика |
| `*` | Страница 404 внутри приложения |

Защищённые маршруты проверяют сессию через API. При `401` клиент сохраняет целевой маршрут и открывает `/login`. После входа он возвращает пользователя на этот маршрут.

## 4. Вход

Экран содержит:

- фиксированное или предзаполненное имя `admin`;
- пароль;
- кнопку входа;
- общую ошибку авторизации;
- индикатор запроса.

Правила:

- Не сохранять пароль в localStorage.
- Не показывать, существует ли пользователь.
- Блокировать повторный submit во время запроса.
- Не перенаправлять внешний URL из query string. Разрешены только внутренние пути.
- Logout завершает сессию и очищает client-side cache.

## 5. Список камер

Каждая карточка содержит:

- имя;
- состояние `disabled`, `connecting`, `online`, `degraded` или `offline`;
- JPEG-снимок или placeholder;
- индикаторы звука, движения и PTZ;
- последнюю ошибку в сокращённом виде;
- ссылку на просмотр;
- ссылку на настройки.

Поведение:

- Список запрашивается после входа.
- Снимок загружается через `GET /api/v1/cameras/{id}/snapshot.jpg` с администраторской cookie.
- В MVP снимок обновляется не чаще одного раза в 10 секунд. В этапе 2 целевой период — 1 секунда для видимой `online`/`degraded` карточки по `50-stage-2.md` §6.
- В этапе 2 не допускаются overlap, очередь запросов и polling скрытой вкладки. После ошибки действует backoff 5 секунд.
- Детальный экран с активным видео не обновляет снимок по таймеру.
- При `offline` показывается последняя диагностика, а не бесконечный loader.
- При `disabled` показывается placeholder вместо снимка. Snapshot polling и autoplay не запускаются.
- Отключённая камера сохраняет историю событий и настройки.
- События SSE обновляют индикатор движения и время последнего события.
- Состояние камеры периодически обновляется через REST. Интервал по умолчанию — 15 секунд.
- При скрытой вкладке polling приостанавливается или снижается.

## 6. Мастер добавления

### Шаг 1. Подключение

Поля:

- имя;
- host или IP;
- ONVIF port, по умолчанию `80`;
- username камеры;
- password камеры;
- необязательный RTSP override.

Рядом с RTSP override должна быть подсказка, что поле нужно только при несовместимости ONVIF GetStreamUri.

### Шаг 2. Probe

Клиент вызывает `POST /api/v1/cameras/probe`.

После успеха он показывает:

- производителя и модель, если камера их вернула;
- профили;
- разрешение и кодеки;
- возможности входящего звука, передачи звука на динамик, движения и PTZ;
- ошибки отдельных проверок.

Probe с частичными ошибками может разрешить продолжение, если найден хотя бы один рабочий профиль. UI обязан показать ограничения.

### Шаг 3. Профиль и снимок

Клиент позволяет выбрать профиль и вызывает `POST /api/v1/cameras/probe/snapshot.jpg`.

- Тело запроса повторяет параметры подключения и выбранный профиль.
- Снимок не сохраняется в localStorage.
- После смены профиля прежний снимок считается устаревшим.
- Пользователь может повторить снимок.
- Ошибка снимка не должна показывать RTSP-URL.

### Шаг 4. Сохранение

Клиент вызывает `POST /api/v1/cameras` и переходит на карточку камеры. Если сервер сохранил камеру, но медиашлюз ещё недоступен, UI показывает `connecting` или `degraded`, а не повторяет Create автоматически.

### Общие правила

- Кнопка «Назад» сохраняет введённые поля только в памяти текущего мастера.
- Закрытие мастера очищает пароль из состояния.
- Submit блокируется на время запроса.
- Повторный клик не создаёт дубликат.
- Ошибка `CAMERA_LIMIT_REACHED` объясняет лимит в 4 камеры.

## 7. Просмотр камеры

Экран содержит:

- имя и состояние;
- плеер;
- выбор Auto, WebRTC и HLS;
- индикатор фактического режима;
- кнопку звука и громкость;
- push-to-talk при `audio_output=supported` в этапе 2;
- выбор WAV/MP3, Play и Stop при `audio_output=supported` в этапе 2;
- fullscreen;
- последнее событие движения;
- PTZ-панель при поддержке;
- ссылку на настройки.

### 7.1 Получение playback

Клиент вызывает `GET /api/v1/cameras/{id}/playback` и получает относительные URL WebRTC и HLS. Ответ не содержит RTSP-URL. В режиме Auto клиент начинает с `preferred`. Если `webrtc=null`, он сразу запускает HLS. Если оба режима равны `null`, успешный ответ считается нарушением контракта.

### 7.2 Автоматический режим

Состояния плеера:

```text
idle → connecting-webrtc → playing-webrtc
                     └────→ connecting-hls → playing-hls
                     └────→ error, если HLS недоступен
```

Правила:

- При `preferred=webrtc` клиент сначала пытается запустить WebRTC.
- При `preferred=hls` клиент сразу запускает HLS.
- При отсутствии WebRTC `playing` в течение 8 секунд клиент закрывает WebRTC и запускает HLS.
- Ошибка ICE или WebRTC также запускает HLS.
- Только один плеер активен в каждый момент.
- Переход не должен оставлять второй RTCPeerConnection или HLS loader.
- UI показывает «WebRTC» или «HLS», а не обещает низкую задержку в обоих режимах.
- Пользователь может вручную повторить WebRTC.

### 7.3 Звук

- Первый запуск использует mute, чтобы соблюдать autoplay policy браузера.
- Включение звука выполняется действием пользователя.
- Если аудиодорожки нет, UI показывает «Звук недоступен».
- Ошибка звука не должна автоматически скрывать видео.
- Переключение WebRTC/HLS сохраняет выбранную громкость в памяти страницы.

### 7.4 Разрыв соединения

- HLS использует ограниченный retry.
- WebRTC не переподключается бесконечно в фоне.
- После исчерпания попыток показывается ошибка и кнопка «Повторить».
- Размонтирование экрана закрывает peer connection, WebSocket, HLS loader и media element.

### 7.5 Микрофон в этапе 2

- Используй push-to-talk только при фактическом WebRTC и `audio_output=supported`.
- Запрашивай микрофон после действия пользователя и только в secure context.
- Останавливай tracks при отпускании, `pointercancel`, скрытии вкладки, разрыве WebRTC и размонтировании.
- Максимальная непрерывная речь — 60 секунд.
- На время речи отключай входящий звук этой камеры и затем восстанавливай настройки.
- HLS показывает требование WebRTC и не имитирует микрофон через upload.
- Полный lifecycle определён в `50-stage-2.md` §7.1.

### 7.6 Файловое воспроизведение в этапе 2

- Принимай только WAV и MP3 до 5 МиБ и 30 секунд.
- Отправляй файл сырым body через admin audio endpoint из OpenAPI. Не отправляй его как JSON или base64.
- Показывай состояние отправки и Stop по `playback_id`.
- Новый Play при активном playback не выполняй и покажи `AUDIO_OUTPUT_BUSY`.
- Не сохраняй файл и аудиобуферы в Web Storage или IndexedDB.
- Ошибка playback не останавливает видео.

## 8. PTZ

### 8.1 Доступность

- При `ptz_continuous=unsupported` элементы движения не отображаются.
- При `unknown` отображается диагностическое состояние и отдельная кнопка проверки недоступна до подтверждения.
- При `ptz_presets=supported` отображается список пресетов.
- Ошибка PTZ не блокирует просмотр.

### 8.2 Move и Stop

Панель поддерживает:

- вверх и вниз;
- влево и вправо;
- диагонали через сочетание pan и tilt;
- zoom in и zoom out;
- Stop.

Поведение кнопки движения:

1. `pointerdown` отправляет Move с `duration_ms=5000`.
2. `pointerup`, `pointercancel` и потеря захвата отправляют Stop.
3. Одно нажатие не продлевается автоматически после пяти секунд.
4. UI отменяет повторную отправку до завершения предыдущего запроса или показывает занятое состояние.
5. При размонтировании панели клиент отправляет Stop best effort.
6. Клиент не использует автоматический retry для Move.

Для клавиатуры аналогичные правила применяются к `keydown` и `keyup`. Повторяющийся `keydown` не создаёт поток запросов.

### 8.3 Пресеты

- Список загружается при открытии панели.
- Выбор пресета отправляет GotoPreset.
- Во время команды выбранный preset отображает pending.
- `PRESET_NOT_FOUND` запускает обновление списка.

## 9. События

На детальном экране отображаются:

- последнее известное состояние движения с явной пометкой, что оно может быть устаревшим;
- время последнего события;
- список последних событий;
- состояние SSE-подключения.

Правила:

- Один EventSource на авторизованное приложение, а не один на каждую карточку.
- При открытии экрана клиент загружает последние события через REST.
- SSE добавляет только новые события.
- После reconnect клиент повторно загружает REST-список и устраняет дубликаты по ID.
- При `401` клиент открывает login.
- Событие содержит ссылку на соответствующую камеру.
- Истории видео и кнопки воспроизведения записи нет.

## 10. Настройки и диагностика

Пользователь может:

- изменить имя;
- изменить профиль;
- изменить адрес и ONVIF port;
- обновить username и password;
- заменить или очистить RTSP override;
- отключить или включить камеру;
- удалить камеру;
- повторить подключение через `POST /api/v1/cameras/{id}/reconnect`.

Правила:

- Password пустой по умолчанию и не заполняется из API.
- Пустой password означает «не менять».
- RTSP override начинается с `rtsp://` и не содержит userinfo. Учётные данные вводятся в отдельных полях.
- Нельзя одновременно передать новый RTSP override и `clear_rtsp_override=true`.
- Disable закрывает плеер перед запросом и не запускает его повторно до Enable.
- Reconnect для отключённой камеры недоступен. Сначала пользователь включает камеру.
- Удаление требует подтверждения с именем камеры.
- После удаления клиент отменяет связанные запросы и переходит к списку.
- Ошибка показывает `code`, безопасное `message` и `request_id`.
- UI не отображает stack trace.

## 11. Мобильная адаптация в этапе 2

- Все экраны поддерживают viewport от 320 px без горизонтального скролла.
- Sidebar становится верхней панелью, сетка и детальный экран используют одну колонку на смартфоне.
- Touch targets имеют размер не менее 44×44 CSS px.
- Плеер, PTZ, формы, события и диалоги не накладываются друг на друга.
- Поля iOS используют font-size не менее 16 px.
- Эмуляция viewport проверяет CSS, но не заменяет Android Chrome и iOS Safari.
- Полные требования и размеры — в `50-stage-2.md` §5.

## 12. Обработка ошибок

| Ситуация | Поведение |
|---|---|
| `401` | Завершить локальную авторизацию и открыть login |
| `403` | Показать отсутствие права без повторного запроса в цикле |
| `404` | Показать удаление или отсутствие камеры |
| `409 CAPABILITY_UNSUPPORTED` | Обновить capabilities и заблокировать действие |
| `409 CAMERA_DISABLED` | Закрыть media и предложить включить камеру |
| `409 AUDIO_OUTPUT_BUSY` | Показать активное воспроизведение и не повторять Play автоматически |
| `413`, `415`, `422` audio errors | Сохранить выбранный файл и показать безопасную причину |
| `502`, `503`, `504` | Сохранить введённые данные и предложить повтор |
| Network error | Показать отсутствие связи с сервером, не смешивать с отсутствием камеры |

## 13. Доступность и безопасность UI

- Все поля имеют label.
- Ошибки полей связаны с элементами формы.
- PTZ и плеер доступны с клавиатуры. Push-to-talk имеет keyboard lifecycle по `50-stage-2.md`.
- Состояние микрофона и playback обозначается текстом, а не только цветом.
- Индикатор состояния не зависит только от цвета.
- Fullscreen имеет доступное имя.
- Секреты не попадают в localStorage и sessionStorage.
- Session token не читается JavaScript. Same-origin fetch использует `credentials: 'same-origin'`.
- `X-Request-ID` сохраняется в клиентской диагностике ошибки без секретов.
- Внешние ссылки из данных камеры не открываются как доверенные URL.
- Строки событий и имён камер выводятся как текст, не HTML.

## 14. Критерии завершения компонента

- Все экраны используют типы из OpenAPI.
- MVP рассчитан на desktop-браузеры. Этап 2 добавляет адаптив от 320 px и обязательные проверки Android Chrome и iOS Safari по `50-stage-2.md`.
- Нет прямых запросов к ONVIF, RTSP или внутреннему go2rtc.
- WebRTC/HLS fallback проходит T-04.
- PTZ обрабатывает отпускание и отмену ввода.
- При выходе со страницы не остаются активные медиасоединения.
- Ошибки и логи браузера не содержат пароли и Bearer-токен ИИ.
